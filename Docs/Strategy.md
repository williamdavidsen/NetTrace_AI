# NetTrace AI Project Strategy

NetTrace AI is a real-time network intelligence platform for collecting packet metadata, streaming events, detecting suspicious traffic patterns, and presenting alerts in a live dashboard.

The V1 goal is a complete local system:

```text
Agent -> Backend API -> PostgreSQL + Redis Stream -> Detection Engine -> Alert API -> Dashboard -> Tests -> Docker
```

Advanced LLM features, complex machine learning, Kubernetes, authentication, and multi-tenant SaaS behavior are intentionally outside V1. The first priority is a small system that works end to end and is easy to review.

## Scope

Included in V1:

- Network metadata collector agent.
- FastAPI backend.
- PostgreSQL data model.
- Redis Stream event pipeline.
- Rule-based anomaly detection.
- Scan, event, alert, explanation, metrics, and status APIs.
- Next.js and TypeScript dashboard.
- Docker Compose local environment.
- Unit, integration, E2E, security, and regression tests.
- GitHub Actions CI.
- Professional README and technical documentation.

Excluded from V1:

- Full packet payload collection.
- Encrypted content inspection.
- Real-time ML model training.
- User authentication.
- Multi-tenant SaaS architecture.
- Kubernetes deployment.
- Real LLM integration.

## Privacy And Security Principles

- Do not collect packet payloads.
- Do not inspect encrypted content.
- Store metadata only.
- Assume local/demo usage.
- Do not commit real secrets.
- Use `.env.example` for configuration examples.
- Validate input and rate-limit backend requests.

Collected metadata fields:

- `timestamp`
- `source_ip`
- `destination_ip`
- `protocol`
- `source_port`
- `destination_port`
- `packet_size`
- `scan_id`

## Technology Stack

- **Backend:** Python, FastAPI, Pydantic, SQLAlchemy, Alembic, Pytest.
- **Data:** PostgreSQL and Redis Streams.
- **Agent:** Python, deterministic sample generator, Scapy metadata capture.
- **Frontend:** Next.js, TypeScript, React, Vitest.
- **DevOps:** Docker, Docker Compose, GitHub Actions.
- **Explanation:** deterministic rule-based explanations in V1.

## Data Model

- **Scan:** one analysis session with target name, status, timestamps, and related events/alerts.
- **PacketEvent:** one metadata record sent by the agent.
- **Alert:** one security finding generated by detection rules.

## Detection Rules

- **Port scan:** one source IP touches many destination ports in a short window.
- **DNS spike:** one source IP generates many DNS events in a short window.
- **Sensitive port activity:** traffic to SSH, Telnet, SMB, or RDP.
- **Large packet:** packet metadata exceeds the large-packet threshold.
- **Unknown protocol:** protocol is outside the expected TCP, UDP, and ICMP set.

## Branch And Commit Strategy

Branch model:

```text
main      -> stable release branch
develop   -> active integration branch
feature/* -> isolated feature or phase branches
```

Commit prefixes:

- `feat:` new feature.
- `fix:` bug fix.
- `test:` test work.
- `docs:` documentation.
- `refactor:` behavior-preserving cleanup.
- `chore:` maintenance and configuration.
- `ci:` CI/CD changes.

## Test Strategy

- **Unit tests:** small functions, schemas, rules, parsers, and explanation templates.
- **Integration tests:** API/database, API/Redis, and agent/backend behavior.
- **E2E tests:** Docker Compose flow from agent event to dashboard alert.
- **Security tests:** invalid input, missing fields, huge payloads, rate limits, and secret scanning.
- **Regression tests:** behavior that earlier phases already completed.

## Minimum Completion Criteria

The project is complete when:

1. `docker compose up --build` works.
2. Backend, agent, frontend, and E2E tests pass.
3. The dashboard shows real data.
4. At least three anomaly types work.
5. The explanation endpoint works.
6. README and technical documentation are professional.
7. At least one demo scenario is available.
8. A `v1.0.0` release tag exists.
